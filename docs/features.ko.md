- [o] S12 — P1: core checklist 항목 F102.2를 위해 text 파일을 읽고 쓴다. 사이드카는 16 MiB 대신 67108864 바이트까지의 요청 줄을 읽고, 답을 HTML escape 없이 쓴다. `read`는 정규 파일의 text를 SHA-256 `version`, `newline` 종류(`lf`, `crlf`, `cr`, `mixed`, `none`), UTF-8 BOM으로 시작하는지와 함께 돌려주고, UTF-8이 아닌 파일, 8388608 바이트를 넘는 파일(읽기 전에 확인한다), 정규 파일이 아닌 경로를 거절한다. `expect`가 version인 `write`는 있는 파일을 자르지 않고 열어 같은 descriptor로 읽은 SHA-256을 비교하고, 다르면 쓰지 않고 `changed on disk`로 실패하며, 같으면 offset 0부터 쓰고 쓴 길이로 자른 뒤 파일을 동기화한다. 그래서 inode, mode, extended attribute, hard link, symbolic link가 그대로 남는다. `expect`가 `null`이면 umask를 적용한 mode 0666으로 새 파일을 만들고, 경로가 있으면 `exists`로 실패한다. `expect`, `text`, `bom`이 빠진 요청은 거절한다. 경로는 `list`처럼 resolve하며, 이름만으로 root를 벗어나는 경로는 조회하기 전에 거절하고, 새 파일은 부모 디렉터리를 resolve한다. macOS에서 `watch`는 정규 파일을 받아 kqueue `NOTE_WRITE`나 `NOTE_EXTEND`에 `{changed: path}`를 보낸다. Linux는 디렉터리만 감시하므로 그곳에서는 `TestWatchReportsAChangedFileContent`를 건너뛴다.
